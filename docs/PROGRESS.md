### Phase 9 / Task 09 (prompts/09-fix-ssti-signature-gap.md) — Close the SSTI Signature Detection Gap

- **Root cause confirmed** (not assumed — traced directly from the Task 01 corpus and rule pattern): `WAFFY-SSTI-001`'s `${...}` (Freemarker/EL) alternative was `\$\{.*(\d+[\*\+]\d+|Runtime|exec)\}` — the keyword/digit-math alternation had to appear *immediately adjacent* to the closing `}`. The corpus's `freemarker_runtime` payload, `${Runtime.getRuntime()}`, has `.getRuntime()` between `Runtime` and the final `}`, so it never matched. The `{{...}}` (Jinja2/Twig) alternative was unaffected (both its corpus cases already matched at 100%).
- **`config/rules/seed_rules.toml`**: **Tested**. `WAFFY-SSTI-001`'s `${...}` alternative changed from `\$\{.*(\d+[\*\+]\d+|Runtime|exec)\}` to `\$\{[^}]*(\d+\s*[\*\+]\s*\d+|Runtime|exec)[^}]*\}` — the keyword can now appear anywhere inside the `${...}` expression, not just immediately before the closing brace. **Worst-case complexity, documented inline in the TOML as required by `CLAUDE.md`**: `[^}]*` (a bounded character class excluding `}`) replaces the previous unbounded `.*` on both sides of the alternation, so a match attempt cannot backtrack across `}` boundaries — linear in input length regardless of how many `${...}` blocks or how much filler text is present, independently bounded by the existing per-request signature-engine time budget. Only this one rule's pattern changed; `waffy/detection/signatures/engine.py` (matcher, paranoia filtering, time budget) was not touched, per constraints.
- **Re-measured results (WSL Ubuntu, Python 3.14.4, this session, `uv run python scripts/attack-lab/run_corpus.py --report`)**: SSTI true-positive rate at **every paranoia level is now 100% (3/3)**, up from the 66.67% (2/3) baseline — `freemarker_runtime` now detected.
